# Decisions

Provisional decisions taken to unblock the build. Each one is reversible; the PRD owner can
overturn any of them. Newest last.

| # | Decision | Status | Why |
| --- | --- | --- | --- |
| D1 | The language is named **Jig**; files are `.jig`. | Provisional (PRD open question) | Matches the repository name. |
| D2 | New language, not a strict Rust subset plus Verus. | Provisional (PRD open question) | The PRD's design (no lifetimes, effects, typed scenarios, dead code as an error) does not fit inside Rust's surface. |
| D3 | Solver: Z3, pinned (currently 5.3.2 from the `z3-solver` wheel). The bootstrap compiler talks SMT-LIB 2 to a solver process over a pipe. | Provisional (PRD open question) | A text interface keeps cvc5 swappable and needs no linking. The self-hosted compiler moves to the C ABI, as the PRD specifies. The solver version is part of every proof-cache key. |
| D4 | Concurrency: fork-join tasks under the `spawn` effect (`std/task`: `all`, `map`, `both`), joined before the call returns, so no task outlives its caller. Task functions may only `spawn`, so results do not depend on scheduling and tests run tasks in order. Native code runs them on a persistent worker pool (the starting thread works through its own batch, so nesting cannot deadlock); programs that use tasks count references atomically while tasks run (D38), others pay nothing. No async, no green threads, no channels yet. | Accepted | Smallest model that is safe with value semantics and deterministic by construction. Effectful tasks (servers) need channels or a scheduler the simulator controls; deferred until a program needs them. |
| D5 | License: MIT, as already in the repository. Governance: see D28. | Provisional (PRD open question) | |
| D6 | Bootstrap path after self-hosting: a checked-in C bootstrap. Once `jigc` compiles itself, its own C output (`bootstrap/jigc.c`, from the release back end) is committed, so building the compiler from source needs only a C compiler: `cc bootstrap/jigc.c` builds a `jigc` that rebuilds itself from the Jig sources. The artifact is regenerated whenever the compiler changes (`bootstrap/update.sh`, which needs only a C compiler) and CI checks it is a fixed point (jigc built by itself produces the same C), with gcc and clang and without Rust; `cargo test` fails while it is stale. The Rust bootstrap compiler is kept, and kept passing the same tests, until `jigc` passes every test suite; then it is frozen. Done: `jigc` passes every suite on its own (`bootstrap/suites.py`, in CI without Rust) and is the `jig` command (`bootstrap/install.sh`); the Rust compiler is frozen as the reference the differential tests compare `jigc` with. | Accepted | Jig already compiles to portable C, so the artifact is plain source any platform's C compiler builds, like Zig's checked-in bootstrap, without keeping a second compiler in another language alive forever. |
| D7 | Memory model: mutable value semantics implemented with non-atomic reference counting and copy-on-write for heap-backed values (`Str`, `List`, `Map`, `Set`, recursive enum payloads, closures). The compiler turns last uses into moves. | Accepted | Value semantics without lifetimes or a GC, as the PRD requires. Atomicity is revisited with D4. |
| D8 | `&mut` appears only on parameter types and call arguments. No reference types in fields, locals or return types. Two `&mut` arguments to one call must be disjoint places. | Accepted | "No references stored inside values" from the PRD, enforced by syntax. |
| D9 | Recursive enum payloads are boxed automatically. | Accepted | Trees stay plain values; agents never write `Box`. |
| D10 | Effects: `io`, `fs`, `net`, `clock`, `rand`, `env`, `spawn`, `ffi`. Pure by default. Panics and failed checks are not effects. | Accepted | The PRD's five plus `ffi`, and `rand`/`env`, which deterministic tests and sandboxing also need. |
| D11 | Methods are declared as `fn Type.name(self, …)`; associated functions as `fn Type.name(…)`. | Accepted | Greppable, mirrors interface declarations, no `impl` blocks. |
| D12 | Generics use angle brackets. In expressions, `<` starts type arguments only if a matching `>` is followed by `(`, `{`, `.`, `)`, `,`, `]` or a line end (the C# rule). | Accepted | Matches the PRD's notation without a turbofish. |
| D13 | Named function bodies return with an explicit `return`; `if`, `match` and closure bodies are expressions whose blocks yield their last expression. | Accepted | Explicit returns where code is long; short forms where it is short. No semicolon subtleties. |
| D14 | Integer overflow, out-of-bounds indexing and division by zero trap in every build unless proven impossible, in which case the check is removed. Unproven `requires`/`ensures` are checked in debug builds only, per the PRD. | Amended by D22 | Memory safety is not optional; contract checks follow the PRD. |
| D15 | Back ends: a MIR interpreter (deterministic test runner), Cranelift (debug builds), LLVM via textual IR compiled by `clang` (release builds). | Superseded by D20 | The PRD's two native back ends, plus an interpreter so tests start in milliseconds with faked effects. |
| D16 | Feature files are standard Gherkin `.feature` files; steps bind with `step "…" fn …` in Jig. | Accepted | PMs write Gherkin; the PRD excludes hooks, tags and backgrounds, which implies standard Gherkin. |
| D17 | Dead-code roots: `main`, the public API of a library root package, and step functions used by a scenario. Tests do not justify code. | Accepted | "Nothing exists unless a feature justifies it." |
| D18 | `Map` and `Set` iterate in insertion order. | Accepted | Deterministic tests and output. |
| D19 | No serde or parser libraries in the bootstrap compiler, and no other large dependencies. | Accepted | Compile speed and the PRD's hand-written front end rule. |
| D21 | Verification conditions come from symbolic evaluation of the typed AST, not MIR: integers are mathematical with range facts (overflow is an obligation, then an assumption), lists are a length plus one SMT array per leaf of the element type, enums are a tag plus every variant's fields, strings and floats are uninterpreted (string length and concatenation are modeled; float comparisons are uninterpreted predicates so NaN stays sound), recursive enums are uninterpreted with tag and field functions. Loops are cut at their invariants with modified places havocked. Calls use contracts only; pure scalar callees are uninterpreted functions. Anything unmodeled is a fresh value (sound, never unsound). | Accepted | The AST keeps quantifiers, `old` and loop structure that MIR has lowered away, and callee contracts are expressions in the callee's own tables. Every construct that is not modeled can only make a proof fail. |
| D20 | The native back end emits C from MIR. Debug builds: `cc -O0`, split into translation units compiled in parallel and cached by content hash. Release builds: one unit through `clang -O2` (LLVM), with the runtime in the same unit and a pooled allocator; checks as in D22. Cranelift stays an option for an in-process debug path later. | Accepted | One code generator instead of two; C gives the platform ABI, struct layout and C interop for free; `clang -O2` *is* the LLVM release path. Cold debug build of a 20k-line program: 3.5 s on 4 cores, 0.3 s when cached; release hello world 60 KB. |
| D22 | Every build keeps every unproven check, contracts included; a proved check is removed. A function's entry checks (`requires`, parameter refinements) are removed when every call site in the program proves them and the function is never used as a value or through a generic bound. | Accepted | Proofs assume contracts: a bounds check removed because a `requires`, `ensures` or loop invariant holds is only safe if that contract is itself proved or checked. Dropping unproven contracts in release builds (D14) would let a violated precondition skip a removed bounds check and read out of bounds. Proving contracts is how a program gets fast, and the program is closed, so a precondition proved at every call needs no check in the callee. |
| D23 | Networking (`std/net`): one request per TCP connection (send, close the sending side, read the reply to the end). A server is `net.serve(addr, state, handle, limit)` with a pure `handle: fn(S, Str) -> (S, Str)`, so its logic is a function tests call directly and its state is a value, not shared memory. Tests run against a simulated network through `std/sim`; code `main` reaches cannot use `std/sim` (E0607). | Accepted | The smallest protocol that needs no framing and works with any TCP peer; value semantics rule out shared server state, and threading it through the handler keeps servers deterministic. Streams, timeouts and concurrent connections come with channels (D4). |
| D24 | Frames: after a call, an `&mut` argument keeps everything the callee's body cannot write. What each function can write to each `&mut` parameter is read off its body (field assignments, `&mut` methods on fields, `&mut` arguments passed on, through callees' frames; recursion, function values and unknown callees write everything) and is part of its callers' proof-cache keys. Amends D21's "calls use contracts only". | Accepted | Without it every `&mut self` method call forgets the whole struct, and agents must write `ensures self.f == old(self.f)` for every field a method leaves alone (the self-hosted lexer needed it on its first call). A frame is a syntactic summary, so proofs stay fast and cache keys stay small; editing a body re-proves its callers only if what it can write changed. |
| D25 | Parallel front end with sequential results. Packages load in waves: every package found so far is parsed (on several threads when there is enough source), and their imports name the next wave; import cycles are found afterwards by the same depth-first walk as before. Body checking gives each thread whole packages and a copy of the type context that records the types it creates; replaying those records in the sequential item order gives every type the id a sequential check would, then each package's tables and bodies are translated. Diagnostics are merged in item order. `JIG_THREADS` overrides the thread count. | Accepted | `jig check` on a 100k-line project must stay under 100 ms; checking on threads must not change a single type id, because lowering, proof-cache keys and generated C depend on them. A shared concurrent type table would have been simpler but makes ids depend on scheduling. |
| D26 | C interop: a function declared without a body, outside the standard library, with the `ffi` effect is the C function of the same name. Signatures are limited to scalars (`Int`, `I32`, `U8`, `U32`, `U64`, `Float`, `Bool`) and `Str` (a NUL-terminated `const char *`, copied when returned), at most 6 integer and 8 `Float` arguments. It lowers to a function whose body is the C call, so its `requires` and `ensures` are checked like any function's (they cannot be proved). Native code declares it under another C name bound to the symbol with an asm label, so it never clashes with a system header; the interpreter finds it with `dlsym` and calls it through one signature filling every argument register. `link NAME` lines in `jig.mod` add C libraries. | Accepted | The PRD's C-ABI-only interop behind an effect, with nothing new to learn: the declaration is an ordinary signature. Register-only signatures cover the C functions agents reach for (libc, libm, small libraries) without a libffi dependency; pointers and structs wait until a use needs them. |
| D27 | Modules (package management): `jig.mod` lists `require PATH VERSION` (a git tag of `https://PATH`) and `replace PATH => DIR`. `jig get` clones each required version into the module cache (`$JIG_HOME/mod`), transitively, and records its commit in `jig.sum`; a commit that differs from the recorded one is refused. Checking and building only read the cache. One version per module, the highest any module requires (minimal version selection). An import whose path starts with a required module's path resolves inside that module, and a module's own imports are relative to its root. Required modules' code is type-checked but not held to the project's lint and dead-code rules, and is not tested or proved with it. | Accepted | Go's model fits Jig's package = directory design and needs no registry: git hosts are the registry, tags are versions, and the commit hash pins the content. Fetching only in `jig get` keeps the millisecond check loop offline and deterministic. |
| D28 | Governance through the alpha: the repository owner decides. Changes land on `main` when CI is green; anything that changes the language or a command's behavior is recorded here first, as provisional, with its reason. The reference and these decisions are the specification until 1.0, and provisional decisions may be reversed without a deprecation period. Versions are `0.MINOR.PATCH` tags; a tag publishes a pre-release (`.github/workflows/release.yml`). | Provisional (PRD open question) | A pre-1.0 language needs to change quickly and on the record; a heavier process (RFCs, a core team) can come with outside contributors. |
| D29 | Table invariants: a struct invariant may state a fact about every element of a list field, or of its elements' fields (`invariant forall i in 0..toks.len(): toks[i].lo <= toks[i].hi`). Both provers prove it where the list changes (at a push, from what is pushed) and assume it where an element is read, as for any struct invariant; where it is not proved, it is checked at run time, over the whole list, where the struct changes. What a struct invariant, a field's `where` clause or a refinement alias may say is exactly what that check evaluates: fields (or `self`), literals, constants and variants, arithmetic, comparisons and logic, `.len()` and `.is_empty()`, list elements and their fields, and `forall` and `exists`; anything else, a call for instance, is an error (E0333). Not now: checking only the element that changed, and invariants over the indices in an enum's payload (an arena struct stating that every child index in `exprs` is below its length), which need pattern tests in contract expressions, in both compilers; so the compiler's own arenas are not annotated. | Provisional (owner's call, 2026-10-28) | Before, the run-time check silently skipped any predicate with a quantifier, an index or a bare constant (`groups <= MAX_GROUPS` in `std/regex`, `self < PRICE` in `examples/vending`), while the prover assumed it wherever the value was read: a function proved to return less than `cap` returned 30 with `cap` 10 in a release build. Checking every accepted form and rejecting the rest makes the assumption sound; the whole-list check is linear, so a struct whose invariant does not prove at its push sites pays for it. The arenas would lift the compiler-contract measure from 39% to at most 57% (`bench/contracts.py`: 209 of 467 functions fail only on such indices); they need the pattern tests first. |
| D30 | HTTP serving: `net.serve_http(addr, state, handle, limit)`, with `net.serve`'s arguments, ends a request after the blank line that ends its headers and the `Content-Length` bytes of body they announce, so clients that keep their side open (browsers, curl) get an answer; the handler gets the raw request and returns the raw reply, and the connection closes after it. A request with `Transfer-Encoding` (a chunked body) is answered `411 Length Required`, one whose `Content-Length` is not a number `400 Bad Request`, without calling the handler. Tests frame `sim.connect`'s requests the same way. Both `serve`s flush standard output before waiting for a connection. | Provisional (owner's call, 2026-10-27) | A hello-world HTTP server compiled but hung under curl: `net.serve` reads until the client closes its sending side, which HTTP clients never do. A separate function keeps `serve` a plain TCP primitive. Parsing the request and building the reply stay in Jig code, so the standard library has no HTTP types to design yet; `examples/http` shows the 30 lines that takes. A server that printed a line and then waited showed nothing, because output was flushed only at exit. |
| D31 | Effect parameters: a function's `effects` clause may name one of its parameters of function type (`fn twice(f: fn() -> Int) -> Int effects {f}`). That parameter takes a function with any effects, and each call performs the effects of the function passed for it, on top of the ones the clause lists. `net.serve` and `net.serve_http` are `effects {net, handle}`. A function with effect parameters can only be called, not used as a function value (E0404); interface methods cannot have them. The built-in methods that take a function (`map`, `filter`, `fold`, `any`, `all`, `sort_by`, ...) have effect parameters too. | Provisional (owner's call, 2026-10-28) | A web server could not read a database: `serve_http`'s handler had to be pure, so it could not call libpq (or touch files, or the clock). Fixing the handler's effects in advance would make every caller of `serve_http` declare all of them; naming the parameter keeps the effects each call has exact, needs no new syntax (the clause is already a list of names, and a misspelt name is still an error) and keeps handlers testable on the simulator. |
| D32 | The documentation site is built by a Jig program, `site/`: a Markdown reader for what the repository's documents use (headings with GitHub's anchors, paragraphs, nested lists with task boxes, tables, fenced and inline code, emphasis, links) that renders through `std/html`, with links between documents kept on the site and links to code sent to GitHub. GitHub Pages serves it, deployed by `.github/workflows/pages.yml` once Pages is turned on and the repository variable `PAGES` is `on`. `std/html` is the escaping HTML engine of `examples/ssr`, moved into the standard library. | Accepted (owner's choice, 2026-10-28) | The owner chose a site the language builds itself over GitHub's Jekyll. It keeps the documents readable on GitHub as they are, tests the language on a real program of its own, and keeps every text on the site escaped by construction. |
| D33 | HTTP client and TLS: `net.fetch(addr, request, tls)` sends a raw request, keeps its sending side open and reads the reply until the server closes (requests say `Connection: close`); with `tls` the connection goes through the system's OpenSSL, opened with `dlopen` the first time a program fetches over TLS, with the certificate checked against the system's roots (or `SSL_CERT_FILE`'s) and the host name, SNI included. `net.get`, `post` and `send` are written in Jig on top of it, with `parse_url`, `request_text`, `parse_response` (`Content-Length`, chunks, or to the end) and, for servers, `parse_request` and `reply`. `get` follows up to five redirects. Reads time out after 30 seconds. In tests, `fetch` answers from `sim.reply`, like `request`. | Provisional (owner's call, 2026-10-28) | Programs could serve HTTP but not call an API. Opening OpenSSL at run time keeps the bootstrap's promise (a C compiler is all it takes to build jigc or any program) and means no program links a TLS library it does not use; the ABI of the dozen functions used is the same in OpenSSL 1.1 and 3. Keeping the protocol in Jig makes it testable on the simulator and lets its contracts prove. Not done: HTTP/2, keep-alive, compressed bodies, client certificates. |
| D34 | Concurrent serving: `net.serve_http_parallel(addr, handle, limit) -> Result<Int, Str>` takes a stateless `handle: fn(Str) -> Str` (with `handle`'s effects) and returns how many requests it answered. Native programs accept on one thread and answer on a pool of workers (`JIG_THREADS`, else twice the processors); such a program counts references atomically, as task programs do, and the runtime locks its output buffer and random generator once a server goes parallel. A connection waits at most 30 seconds for its client. The interpreter, so `jig test`, answers one request at a time. | Provisional (owner's call, 2026-10-28) | `serve_http` threads its state through each request, so it cannot answer two at once; a handler that keeps its state elsewhere (a database, files) can. A stateless handler needs no locks in the language, values are shared copy-on-write, and the effects a handler may have are the ones it declares. Not done: a parallel `serve` for raw TCP, a limit on queued connections. |
| D35 | C interop with byte buffers: a C function may take `List<U8>`, passed as a `const uint8_t *` to its bytes, and `&mut List<U8>`, passed as a `uint8_t *` to a buffer of the list's length that C may write; what it writes is in the list after the call, whose length does not change (size it first: `[0 as U8].repeat(n)`). The length is never passed implicitly: pass it as an `Int`. Natively the C function gets the list's own storage (made unique first); the interpreters copy in and out. Opaque pointers stay `Int`, and a struct passed by pointer is a `&mut List<U8>` of its size read and written by byte offset. | Provisional (owner's call, 2026-10-28) | Buffers are what keeps most C libraries out of reach (`read`, `write`, hashing and compression libraries, libpq's binary parameters); with them, a struct or an out-parameter is bytes at known offsets, which needs no new syntax. Not done: callbacks (a C function calling Jig). jigc's interpreter, written in Jig, cannot be re-entered from C (nothing can hold a mutable reference to it across the call), and a callback that worked only in native code would make `jig run` and `jig test` behave differently from a build, so a library that calls back still needs a small C wrapper. A returned `uint8_t *` stays an `Int`. |
| D36 | Editor support: `jig lsp` is a Language Server Protocol server over stdio. It keeps the open documents' texts and, after each change, checks the project the document belongs to as `jig check` does, the open texts in place of the files, publishing every file's diagnostics (all of them errors, with their codes). Hover gives an expression's type, or a function's signature; definition finds where a function, method, local, constant or variant is declared; formatting is `jig fmt`'s layout. `editors/vscode` is a VS Code extension that starts it, with a grammar for highlighting. `io.read(n)` (the bytes a message's `Content-Length` announces) joins `std/io` for it, in both compilers. The server is jigc's alone: the Rust compiler is frozen as the reference for the language (D6), and an editor protocol is tooling the differential tests have no use for. | Provisional (owner's call, 2026-10-28) | Agents read diagnostics from `jig check --json` and `jig mcp`; people read them in an editor. Checking the whole project on each change is what `jig check` already does in milliseconds on small projects, and keeps one checker. Not done: completion, references, rename, hover on a declaration's own name (only expressions have types), and incremental checking (a 100k-line project takes `jig check`'s time per change). |
| D37 | Windows: jigc, which ships as `jig`, and the programs it builds run on Windows x86-64 through MinGW-w64 (its `gcc`, with winpthreads). The runtime stays one file whose Windows parts are `#ifdef _WIN32`: Winsock sockets (programs link `-lws2_32`, statically), `LoadLibrary` for C libraries and for OpenSSL (`libssl-3-x64.dll`), standard streams in binary mode so that output is the same bytes as on POSIX, its own `getline` and `memmem`, and `PWD` set from the working directory, with `/` between names, unless the shell set it to a path with a drive. jigc keeps paths with `/` and a drive (`C:/Users/me`), takes `\` in the paths it is given, runs the C compiler, the SMT solver and git through `cmd.exe` with its quoting (`selfhost/sema/host.jig`), names executables `.exe`, and calls C functions from its interpreter by Windows x64's convention, which passes arguments by position. The Rust compiler is not ported (D6). | Provisional (owner's call, 2026-10-28) | Windows was the last platform the plan named. MinGW-w64 keeps the bootstrap's promise that a C compiler is all it takes: it has the pthreads, `clock_gettime`, `nanosleep` and `dirent` the runtime uses, which leaves sockets, libraries, the shell and paths to port, and the generated C is GNU C11, which MSVC does not compile. CI's Windows job builds jigc from the checked-in C, checks that it reproduces that C, and runs the test suites. Not done: MSVC, ARM64 Windows, and Windows' own certificate store for TLS (OpenSSL reads `SSL_CERT_FILE`). |
| D38 | jigc checks on several threads, as the bootstrap compiler does (D25). A load wave's files are parsed with `std/task` once the wave holds 256 KiB of source; once the program does, function bodies are checked in about eight runs of whole files, each on its own copy of the checker. Each run's new types and units are replayed into the shared table in order and the type ids in its tables and bodies renamed (on the threads again), so the result is the sequential one: the C jigc generates for itself is byte for byte the same on one thread or four. `JIG_THREADS=1` checks on one thread. Reference counts in a program that uses tasks or a parallel server are atomic only while threads can share values: `jig_sharing` is raised while a batch of tasks runs and while a parallel server serves, and otherwise counts are plain additions. | Provisional (owner's call, 2026-10-28) | A full check of the 98k-line benchmark took jigc 345 to 370 ms on one thread here, against the bootstrap compiler's 115 to 135 ms on four. Parsing and body checking are four fifths of the work and independent per file. Counting atomically all the time cost 14% (345 against 394 ms), which is why phase 4's parallel parse gained little; counting atomically only while threads share values costs one predictable branch per count (2.5% more instructions, no measurable time). Signatures are resolved the same way, in the same runs of files, with methods registered afterwards in function order so that the first of two with one name is kept, and `jig check` exits without freeing the checker's state (17 ms of the 80k-line check; the project check keeps each program's state until it returns, so `jig hook` and `jig mcp` hold one per program package at once). Not done: a smaller AST (an expression is 72 bytes, so jigc touches twice the memory the bootstrap compiler does, 95 MB against 46, and page faults are a large part of its time on a virtual machine). |
| D39 | The bootstrap carries its proofs. `bootstrap/proofs.txt` records, for each function of `selfhost/`, its proof cache key (which covers its text, the contracts and frames of what it calls, the standard library, the solver's version) and the kind, place and outcome of each obligation; `jigc cc DIR STD PROOFS` removes the checks those proofs discharge, as `jig build` does from `.jig/proofs`, and functions whose key no longer matches keep their checks. `bootstrap/update.sh` proves `selfhost/` and rewrites the file when Z3 is installed, so `bootstrap/jigc.c` stays deterministic, and a fixed point, on machines without it. | Provisional (owner's call, 2026-10-28) | The shipped `jig` was built with every check in it, so its own proofs bought it nothing: the 80k-line benchmark took 211 ms to check, against 177 ms with the checks its proofs remove (best of 20, four threads; 340 against 302 ms on one). Trusting the file is trusting a committed artifact, as with `jigc.c` itself, and a stale entry cannot remove a check: its key no longer matches. |
