# Decisions

Provisional decisions taken to unblock the build. Each one is reversible; the PRD owner can
overturn any of them. Newest last.

| # | Decision | Status | Why |
| --- | --- | --- | --- |
| D1 | The language is named **Jig**; files are `.jig`. | Provisional (PRD open question) | Matches the repository name. |
| D2 | New language, not a strict Rust subset plus Verus. | Provisional (PRD open question) | The PRD's design (no lifetimes, effects, typed scenarios, dead code as an error) does not fit inside Rust's surface. |
| D3 | Solver: Z3, pinned (currently 5.3.2 from the `z3-solver` wheel). The bootstrap compiler talks SMT-LIB 2 to a solver process over a pipe. | Provisional (PRD open question) | A text interface keeps cvc5 swappable and needs no linking. The self-hosted compiler moves to the C ABI, as the PRD specifies. The solver version is part of every proof-cache key. |
| D4 | Concurrency: fork-join tasks under the `spawn` effect (`std/task`: `all`, `map`, `both`), joined before the call returns, so no task outlives its caller. Task functions may only `spawn`, so results do not depend on scheduling and tests run tasks in order. Native code runs them on a persistent worker pool (the starting thread works through its own batch, so nesting cannot deadlock); programs that use tasks count references atomically, others pay nothing. No async, no green threads, no channels yet. | Accepted | Smallest model that is safe with value semantics and deterministic by construction. Effectful tasks (servers) need channels or a scheduler the simulator controls; deferred until a program needs them. |
| D5 | License: MIT, as already in the repository. Governance: see D28. | Provisional (PRD open question) | |
| D6 | Bootstrap path after self-hosting: a checked-in C bootstrap. Once `jigc` compiles itself, its own C output (`bootstrap/jigc.c`, from the release back end) is committed, so building the compiler from source needs only a C compiler: `cc bootstrap/jigc.c` builds a `jigc` that rebuilds itself from the Jig sources. The artifact is regenerated whenever the compiler changes (`bootstrap/update.sh`, which needs only a C compiler) and CI checks it is a fixed point (jigc built by itself produces the same C), with gcc and clang and without Rust; `cargo test` fails while it is stale. The Rust bootstrap compiler is kept, and kept passing the same tests, until `jigc` passes every test suite; then it is frozen. | Provisional | Jig already compiles to portable C, so the artifact is plain source any platform's C compiler builds, like Zig's checked-in bootstrap, without keeping a second compiler in another language alive forever. |
| D7 | Memory model: mutable value semantics implemented with non-atomic reference counting and copy-on-write for heap-backed values (`Str`, `List`, `Map`, `Set`, recursive enum payloads, closures). The compiler turns last uses into moves. | Accepted | Value semantics without lifetimes or a GC, as the PRD requires. Atomicity is revisited with D4. |
| D8 | `&mut` appears only on parameter types and call arguments. No reference types in fields, locals or return types. Two `&mut` arguments to one call must be disjoint places. | Accepted | "No references stored inside values" from the PRD, enforced by syntax. |
| D9 | Recursive enum payloads are boxed automatically. | Accepted | Trees stay plain values; agents never write `Box`. |
| D10 | Effects: `io`, `fs`, `net`, `clock`, `rand`, `env`, `spawn`, `ffi`. Pure by default. Panics and failed checks are not effects. | Accepted | The PRD's five plus `ffi`, and `rand`/`env`, which deterministic tests and sandboxing also need. |
| D11 | Methods are declared as `fn Type.name(self, …)`; associated functions as `fn Type.name(…)`. | Accepted | Greppable, mirrors interface declarations, no `impl` blocks. |
| D12 | Generics use angle brackets. In expressions, `<` starts type arguments only if a matching `>` is followed by `(`, `{`, `.`, `)`, `,`, `]` or a line end (the C# rule). | Accepted | Matches the PRD's notation without a turbofish. |
| D13 | Named function bodies return with an explicit `return`; `if`, `match` and closure bodies are expressions whose blocks yield their last expression. | Accepted | Explicit returns where code is long; short forms where it is short. No semicolon subtleties. |
| D14 | Integer overflow, out-of-bounds indexing and division by zero trap in every build unless proven impossible, in which case the check is removed. Unproven `requires`/`ensures` are checked in debug builds only, per the PRD. | Amended by D22 | Memory safety is not optional; contract checks follow the PRD. |
| D15 | Back ends: a MIR interpreter (deterministic test runner), Cranelift (debug builds), LLVM via textual IR compiled by `clang` (release builds). | Superseded by D20 | The PRD's two native back ends, plus an interpreter so tests start in milliseconds with faked effects. |
| D16 | Feature files are standard Gherkin `.feature` files; steps bind with `step "…" fn …` in Jig. | Accepted | PMs write Gherkin; the PRD excludes hooks, tags and backgrounds, which implies standard Gherkin. |
| D17 | Dead-code roots: `main`, the public API of a library root package, and step functions used by a scenario. Tests do not justify code. | Accepted | "Nothing exists unless a feature justifies it." |
| D18 | `Map` and `Set` iterate in insertion order. | Accepted | Deterministic tests and output. |
| D19 | No serde or parser libraries in the bootstrap compiler, and no other large dependencies. | Accepted | Compile speed and the PRD's hand-written front end rule. |
| D21 | Verification conditions come from symbolic evaluation of the typed AST, not MIR: integers are mathematical with range facts (overflow is an obligation, then an assumption), lists are a length plus one SMT array per leaf of the element type, enums are a tag plus every variant's fields, strings and floats are uninterpreted (string length and concatenation are modeled; float comparisons are uninterpreted predicates so NaN stays sound), recursive enums are uninterpreted with tag and field functions. Loops are cut at their invariants with modified places havocked. Calls use contracts only; pure scalar callees are uninterpreted functions. Anything unmodeled is a fresh value (sound, never unsound). | Accepted | The AST keeps quantifiers, `old` and loop structure that MIR has lowered away, and callee contracts are expressions in the callee's own tables. Every construct that is not modeled can only make a proof fail. |
| D20 | The native back end emits C from MIR. Debug builds: `cc -O0`, split into translation units compiled in parallel and cached by content hash. Release builds: one unit through `clang -O2` (LLVM), with the runtime in the same unit and a pooled allocator; checks as in D22. Cranelift stays an option for an in-process debug path later. | Accepted | One code generator instead of two; C gives the platform ABI, struct layout and C interop for free; `clang -O2` *is* the LLVM release path. Cold debug build of a 20k-line program: 3.5 s on 4 cores, 0.3 s when cached; release hello world 60 KB. |
| D22 | Every build keeps every unproven check, contracts included; a proved check is removed. A function's entry checks (`requires`, parameter refinements) are removed when every call site in the program proves them and the function is never used as a value or through a generic bound. | Accepted | Proofs assume contracts: a bounds check removed because a `requires`, `ensures` or loop invariant holds is only safe if that contract is itself proved or checked. Dropping unproven contracts in release builds (D14) would let a violated precondition skip a removed bounds check and read out of bounds. Proving contracts is how a program gets fast, and the program is closed, so a precondition proved at every call needs no check in the callee. |
| D23 | Networking (`std/net`): one request per TCP connection (send, close the sending side, read the reply to the end). A server is `net.serve(addr, state, handle, limit)` with a pure `handle: fn(S, Str) -> (S, Str)`, so its logic is a function tests call directly and its state is a value, not shared memory. Tests run against a simulated network through `std/sim`; code `main` reaches cannot use `std/sim` (E0607). | Accepted | The smallest protocol that needs no framing and works with any TCP peer; value semantics rule out shared server state, and threading it through the handler keeps servers deterministic. Streams, timeouts and concurrent connections come with channels (D4). |
| D24 | Frames: after a call, an `&mut` argument keeps everything the callee's body cannot write. What each function can write to each `&mut` parameter is read off its body (field assignments, `&mut` methods on fields, `&mut` arguments passed on, through callees' frames; recursion, function values and unknown callees write everything) and is part of its callers' proof-cache keys. Amends D21's "calls use contracts only". | Accepted | Without it every `&mut self` method call forgets the whole struct, and agents must write `ensures self.f == old(self.f)` for every field a method leaves alone (the self-hosted lexer needed it on its first call). A frame is a syntactic summary, so proofs stay fast and cache keys stay small; editing a body re-proves its callers only if what it can write changed. |
| D25 | Parallel front end with sequential results. Packages load in waves: every package found so far is parsed (on several threads when there is enough source), and their imports name the next wave; import cycles are found afterwards by the same depth-first walk as before. Body checking gives each thread whole packages and a copy of the type context that records the types it creates; replaying those records in the sequential item order gives every type the id a sequential check would, then each package's tables and bodies are translated. Diagnostics are merged in item order. `JIG_THREADS` overrides the thread count. | Accepted | `jig check` on a 100k-line project must stay under 100 ms; checking on threads must not change a single type id, because lowering, proof-cache keys and generated C depend on them. A shared concurrent type table would have been simpler but makes ids depend on scheduling. |
| D26 | C interop: a function declared without a body, outside the standard library, with the `ffi` effect is the C function of the same name. Signatures are limited to scalars (`Int`, `I32`, `U8`, `U32`, `U64`, `Float`, `Bool`) and `Str` (a NUL-terminated `const char *`, copied when returned), at most 6 integer and 8 `Float` arguments. It lowers to a function whose body is the C call, so its `requires` and `ensures` are checked like any function's (they cannot be proved). Native code declares it under another C name bound to the symbol with an asm label, so it never clashes with a system header; the interpreter finds it with `dlsym` and calls it through one signature filling every argument register. `link NAME` lines in `jig.mod` add C libraries. | Accepted | The PRD's C-ABI-only interop behind an effect, with nothing new to learn: the declaration is an ordinary signature. Register-only signatures cover the C functions agents reach for (libc, libm, small libraries) without a libffi dependency; pointers and structs wait until a use needs them. |
| D27 | Modules (package management): `jig.mod` lists `require PATH VERSION` (a git tag of `https://PATH`) and `replace PATH => DIR`. `jig get` clones each required version into the module cache (`$JIG_HOME/mod`), transitively, and records its commit in `jig.sum`; a commit that differs from the recorded one is refused. Checking and building only read the cache. One version per module, the highest any module requires (minimal version selection). An import whose path starts with a required module's path resolves inside that module, and a module's own imports are relative to its root. Required modules' code is type-checked but not held to the project's lint and dead-code rules, and is not tested or proved with it. | Accepted | Go's model fits Jig's package = directory design and needs no registry: git hosts are the registry, tags are versions, and the commit hash pins the content. Fetching only in `jig get` keeps the millisecond check loop offline and deterministic. |
| D28 | Governance through the alpha: the repository owner decides. Changes land on `main` when CI is green; anything that changes the language or a command's behavior is recorded here first, as provisional, with its reason. The reference and these decisions are the specification until 1.0, and provisional decisions may be reversed without a deprecation period. Versions are `0.MINOR.PATCH` tags; a tag publishes a pre-release (`.github/workflows/release.yml`). | Provisional (PRD open question) | A pre-1.0 language needs to change quickly and on the record; a heavier process (RFCs, a core team) can come with outside contributors. |
